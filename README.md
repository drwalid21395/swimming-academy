## 🛡️ نظام الصلاحيات (إداري فقط للأدمن)

- **مدير النظام (`admin`)** هو **الوحيد** المخوّل بـ:
  - **إضافة / حذف / تعديل المستخدمين** (أسماء المستخدمين وكلمات المرور والأدوار) من صفحة **المستخدمين** `/users`.
  - **تحديد / تعديل صلاحيات جميع الأدوار** من صفحة **الأدوار والصلاحيات** `/roles` (لكل وحدة: عرض/إضافة/تعديل/حذف/اعتماد).
  - **إعادة تعيين كلمة مرور أي مستخدم** من زر "كلمة مرور جديدة" بجانب كل مستخدم.
- **لا يحق لأي مستخدم آخر** (غير الأدمن) تغيير صلاحياته أو صلاحيات غيره، ولا تغيير أسماء/كلمات مرور الآخرين، ولا إدارة المستخدمين. نظام الصلاحيات يمنع ذلك تماماً على مستوى الخادم (وليس واجهة فقط).
- **كل مستخدم** يمكنه تغيير **كلمة المرور الخاصة به فقط** من صفحة الملف الشخصي (يتطلب إدخال كلمة مروره الحالية). لا يوجد أي وسيلة لأي مستخدم بتغيير اسم المستخدم أو الدور لنفسه.

## 🚀 النشر على Vercel

المشروع مهيّأ للنشر كدالة Serverless على Vercel عبر:

- `api/index.js` — نقطة دخول Serverless (`module.exports = require('../server')`)
- `vercel.json` — إعدادات البناء وتضمين القوالب (`views`, `public`, `lib`, `routes`, `db`, `src`)
- `server.js` — يقوم بـ `app.listen` فقط خارج بيئة Vercel

### المتغيرات البيئية المطلوبة

| المتغير | الوصف | مثال |
|---|---|---|
| `DB_URL` | رابط قاعدة البيانات (Turso/libsql) | `libsql://swimming-academy-drwalid21395.aws-eu-west-1.turso.io` |
| `DB_TOKEN` | توكن الوصول لقاعدة البيانات | (من لوحة Turso) |
| `SESSION_SECRET` | سرّ توقيع الكوكيز | نص عشوائي طويل |

> عند وجود `DB_URL` يُعاد التوجيه تلقائياً إلى القاعدة البعيدة؛ وعند غيابها (محلياً) تُستخدم `data.db`.

### النشر من سطر الأوامر

```bash
npm i -g vercel
vercel login
vercel deploy --prod
```
